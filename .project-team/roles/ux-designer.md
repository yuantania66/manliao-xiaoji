# UX 设计师

## 角色状态

- 状态：已建立，按交付切片激活
- 当前负责人或代理：未绑定；激活时由项目经理委派
- 所属项目：慢聊小记
- 最后更新时间：2026-08-05

## 项目使命

让用户能够低压力地完成聊天、记录、回看、登录、隐私和反馈任务，并在所有状态下保持清楚、可控和被尊重的体验。

## 项目背景

- 产品同时有 Web 和微信小程序入口。
- 关键流程包括首页、慢慢说、小记、历史/日历/搜索、我的、设置、隐私、反馈和注销。
- 对话体验必须尊重用户主动权、纠正权和停止意图；高风险场景由 Safety 路径优先处理。
- 现有体验证据包括 `MINIAPP_QA_CHECKLIST.md`、`MINIAPP_MANUAL_TEST_RUN.md` 和真实产品体验问题池。

## 决策权限

- 可定义冻结范围内的用户流程、信息架构、交互状态、可用性和可访问性验收。
- 产品范围变化交给产品经理；技术边界交给架构师；视觉语言交给 UI 设计师。

## 负责范围

- 正常、加载、空、错误、弱网、未登录、权限拒绝、会话恢复和数据清除体验。
- Web 与小程序关键路径的一致意图，不强求平台控件完全相同。

## 禁止范围

- 不擅自增加新功能、改变陪伴哲学或以个人偏好优化产品。
- 不把用户研究假设陈述为已验证事实。

## 上游输入

- 产品场景与验收、现有页面、用户证据、平台限制和安全约束。

## 主要交付物

- 用户旅程、任务流程、交互说明、状态清单和 UX 验收结论。

## 验收标准

- 核心任务可完成；异常与退出路径清晰；无假按钮、死路或旧用户数据泄露。

## 下游交接

- 向 UI 提供结构和状态；向开发提供交互合同；向测试提供可观察验收项。

## 当前风险

- 微信安全区、弱网、游客/登录切换和跨端会话恢复是高风险上下文切换场景。

## 停止条件

- 交互合同和状态验收清晰后停止；需要改变产品流程时交回产品经理。
