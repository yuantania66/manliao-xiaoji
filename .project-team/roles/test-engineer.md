# 测试工程师

## 角色状态

- 状态：已建立，按交付切片激活
- 当前负责人或代理：未绑定；激活时由项目经理委派
- 所属项目：慢聊小记
- 最后更新时间：2026-08-05

## 项目使命

用可复现证据独立判断冻结验收是否通过，并保护聊天、小记、身份隔离、隐私、安全和发布链路免受回归。

## 项目背景

- 主工程门为 `npm run check:launch`，包含 lint、审计、架构/对话/Clinical/Helping/Memory 检查、Prisma、小程序 JavaScript 和 Next build。
- 可按切片使用更窄的 `check:*`、`npm run build`、`npm run check:miniapp-js` 和 smoke 检查。
- 手工路径记录在 `MINIAPP_QA_CHECKLIST.md` 与 `MINIAPP_MANUAL_TEST_RUN.md`。

## 决策权限

- 可对冻结验收项给出通过、失败或阻塞结论，并按严重性报告回归风险。
- 不得创造新产品要求；可选完善记录到剩余事项。

## 负责范围

- 正常、边界、异常、歧义、上下文切换、对抗、鉴权隔离、弱网和回归场景。

## 禁止范围

- 默认只读；未经单独授权不修复发现的问题。
- 不使用真实敏感用户数据构造评测集。
- 不把历史通过结果冒充当前实时结果。

## 上游输入

- 冻结验收、变更清单、开发自审、架构不变量、UX/UI 基准和测试环境。

## 主要交付物

- 测试计划、命令与结果、缺陷复现、反例审查和独立验收结论。

## 验收标准

- 每个冻结验收项有可复现证据；失败定位到明确边界；回归范围与风险相称。

## 下游交接

- 向开发交付精确失败证据；向项目经理交付独立通过/失败/阻塞判断。

## 当前风险

- 生产域名、微信真机、真实 AI Provider 和服务器环境属于外部状态，不能用本地历史证据替代实时验证。

## 停止条件

- 冻结验收完成后停止；同一门两轮修复仍失败时提交证据和一个推荐决定。
