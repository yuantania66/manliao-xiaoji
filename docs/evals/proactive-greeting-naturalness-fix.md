# 主动欢迎语自然度修复

日期：2026-07-29

## 问题

用户实际看到的欢迎语为：

```text
随时可以在这儿说点什么，或者只是待一会儿。
```

服务日志证明页面每次打开都会重新调用欢迎语接口，因此重复并非服务端响应缓存。
根因位于主动欢迎语自己的责任边界：

1. Prompt 以大量禁止项为主，具体的正向聊天动作不清楚；
2. Validator 强制出现“说、聊、放、留、在这、这里”等词，奖励许可式文案；
3. “待一会儿、陪你、慢慢来”没有被视为提前等待或收口；
4. 最近欢迎语在生成前被过滤，模型与 Validator 都无法识别重复；
5. 游客历史使用 `sessionStorage`，不同标签页互不可见。

## 第一轮修改

- Prompt 版本升级为 `chat-proactive-greeting-v3`。
- 欢迎语唯一动作改为：助手承担开场成本，提供一个具体、轻量、可用几个字回答、
  不依赖用户状态假设的日常话头。
- 移除“必须包含说/聊/在这”等关键词白名单；克制的正常口语语气词不再被一概禁止。
- Validator 拒绝许可声明、陪伴/等待、提前收口、空泛问题、多个问题及高度相似欢迎语。
- 使用字符 bigram Dice 相似度检查最近三条欢迎语，阈值为 `0.72`。
- 人工首轮验证发现“哪首歌忍不住单曲循环”与“哪首歌单曲循环了好几遍”
  字符相似度不足但话题完全相同；因此增加 system-defined topic signature，
  对音乐、影视、饮食、阅读、照片/颜色、物件、地点和声音类别做近期复用检查。
- 登录态从既有 ChatMessage 窗口取得最近欢迎语；游客态以最小
  `localStorage` 列表跨标签页共享最近三条。
- 最近欢迎语原文只用于内部 Validator，不进入外部模型 Prompt。模型只收到近期欢迎语
  数量、system-defined topic labels 和更换话题/句式的要求。
- 游客缓存会折叠连续欢迎语，只保留连续欢迎段中的最新一条；已有用户/助手对话不删除。
- 模型连续两次失败时不再以固定陪伴文案覆盖；服务返回失败且不创建欢迎消息。
  显式 deterministic 开发模式保留一条具体话题文案。

## 第二轮修订：欢迎语不等于提问

人工验收进一步暴露两个合同错误：

1. `v3` 把“助手承担开场成本”收窄成“欢迎语必须提出一个问题”，实际仍把
   回答义务交给用户；
2. 用户回答该问题后，普通 Planner 为避免连续采访设置
   `questionPolicy=none`，却只剩宽泛的
   `acknowledge_without_psychologizing`。`嗯，吃到了就好。` 没有命中旧
   closure 或评价词规则，因此被 Validator 接受。

本轮按责任层修订：

- 欢迎 Prompt 升级为 `chat-proactive-greeting-v4`，本地先选择
  `simple_greeting`、`open_statement` 或 `light_question`，模型只实现
  被选动作；
- 问题型欢迎语在“当前 + 最近两条”窗口中最多一次，不能连续出现；
- 非问题欢迎语不再因缺少问号被拒绝；许可、等待、陪伴、环境/关系猜测、
  重复句式与重复话题边界继续保留；
- 外部 Prompt 只接收 system-defined move/topic labels，不接收最近欢迎语原文；
- ordinary ResponsePlan Prompt 升级为 `chat-response-plan-v21`；
- 最近 Assistant 是主动欢迎语时，首个用户轮使用
  `respond_to_proactive_greeting`。一次贴着当前内容的具体跟进可选，不强制；
- Validator 拒绝空洞确认、裸复述、通用好坏评价、泛泛追问，以及
  `知道了/收到/就好/就行` 式收口；任意回复仍最多一个问题；
- Assistant 问题后的回答继续使用既有“默认不再开启第二个采访问题”
  规则，包含问题型欢迎语后的首个用户回应。

第二次人工验收又出现：

```text
傍晚的上海刚入夜，这会儿正好适合慢慢聊几句。
```

这里的“上海”来自服务端时区标签，不是用户位置；18:19 也不能证明用户当地
已经入夜。修订后，服务端时区和时间不再进入欢迎语 Prompt；Prompt 与
Validator 均禁止地名、用户当地时间、昼夜阶段、天气和“当前适合聊天”等
判断。`simple_greeting` 与 `open_statement` 仍是不同生成偏好，但 Validator
按更稳健的“非问题边界”验收，避免安全的非问题措辞因表面类型差异导致整条
欢迎语失败。

第三次人工验收出现：

```text
助手：最近有听到什么好听的歌吗？
用户：我不爱听歌
助手：那平时喜欢做点什么打发时间？
```

这里不是模型绕过 Planner，而是 Planner 优先匹配“正在回应主动欢迎语”，把
`questionPolicy` 设成了 `optional_after_answer`；“正在回答助手问题”的既有
`none` 规则被后者覆盖。修订后，只要主动欢迎语本身是问题，用户的紧邻回应就
沿用普通问题回答规则：不得再开启第二个问题。只有非问题欢迎语后的具体用户
内容仍可选择一次贴题跟进；Surface 同时禁止为了维持回答而强行切换话题。

## 本地验证

- 24 个许可式、陪伴式、空泛式和收口式反例全部被拒绝；
- 20 个问候、非问题陈述和具体问题样例全部保留；
- 三种欢迎动作选择与“三次窗口最多一次问题”回归通过；
- 截图原句被拒绝；
- 相同和近似重复被拒绝，不同话题不误拒；
- 截图中的两条“歌曲单曲循环”复述及另外 6 组话题复用反例被拒绝；
- 连续游客欢迎语折叠回归通过；
- 游客最近欢迎语解析、三条窗口、去重和跨标签页存储合同通过；
- deterministic 开发模式的多动作候选序列通过同一 Validator；
- 20 种欢迎语后用户输入均进入独立承接动作；
- 24 个空洞确认、裸复述、通用评价、泛泛追问和收口反例被拒绝；
- 20 个欢迎问题后的换题追问反例被拒绝，截图原句被明确覆盖；
- 截图中的上海、入夜与适合聊天三重无依据判断被拒绝；
- 外部欢迎 Prompt 不再包含服务端时区、日期或时间；
- `npm run check:ai-base`、`npm run check:assistant-grounding` 与
  `npx tsc --noEmit` 通过。

真实 Qwen A/B 属于外部模型调用，必须在独立授权后运行；本文不伪造模型输出。
