## 跨样本根因

### 1. 普通修复仍被固定词形控制

Planner 已给出具体子类型和相邻目标证据，但 Validator 实际上仍分别要求一组固定的
“否定词＋子类型词”。因此以下功能完整的自然修复被误拒：

- 具体承担并否定“列方案／出主意”，但没有再次出现预设的“建议”词形；
- 说明“光说会听／认真听并没有抓住重点”，但没有固定“停止／不该”词；
- 引用“应该勇敢点”并明确说不该说，但未命中“勇敢一点”的固定形式；
- 承担“不该提放松练习／岔开话题”，但未命中预设话题切换词形组合。

这违反了已冻结的“Validator 判断目标动作是否被功能性处理，不要求固定停止/撤回词”合同。

### 2. 情绪证据等价表达仍有误拒

“心里有点堵”在回复中自然变化为“心里堵着／这股堵”时仍被判为没有承接。证据合同
虽然已统一到 Planner，但 Validator 的回复侧等价判断仍依赖过窄表面形式。

### 3. 当前话题边界仍有漏放

Validator 能拒绝“换个话题／聊点别的”，但未稳定识别以下相同功能：

- “聊聊别的什么”；
- “说说别的什么”；
- “别的让你烦的事”。

前两类把选择权引向无关内容；后一类还引入了用户未提供的原因或事件。5 个真实失败的
第二次输出因此被接受。

### 4. Surface 再生成仍重复违反通用边界

真实 Surface 失败集中于几类跨场景行为：

- 主动换话题或用别的内容转移注意力；
- 把情绪评价为“正常／没关系”；
- 在用户没有要求暂停时建议“待一会儿”；
- 添加用户没有提供的事件、原因或新的情绪类别。

这些不是单个样本文案问题，而是 Prompt 与再生成修复指令未稳定表达动作范围。

## 是否需要修改代码

结论：需要修改代码。

依据不是候选 4 未达到 100%，而是同一冻结合同下同时出现了可重复的 Validator 误拒、
Validator 漏放和 Surface 跨场景边界失败。只重新运行模型不能修正这三类确定性合同偏差；
只放宽 Validator 又会进一步放过 5 个已确认的真实失败。

修改仍必须限制在批次 1.5 的现有责任层：

1. Validator 用“承担关系＋目标证据＋功能性否定”组合判断普通修复，不扩张固定词表；
2. Validator 基于 Planner 证据类别和自然派生形式判断情绪承接；
3. Validator 统一判断“已知当前内容”与“未知其他内容／原因事件”的作用域；
4. Surface 与 regeneration 指令明确保持所选动作范围，不提供其他话题、调节或暂停。
